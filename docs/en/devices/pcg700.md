# PCG-700 (HAL Laboratory) - programmable character generator for the MZ-700

The PCG-700 by HAL Laboratory is an external expansion unit for the real
MZ-700. It has 2 KB of RAM that replaces the character generator (CG-ROM)
for the character codes 80h-FFh of both character sets; codes 00h-7Fh are
always taken from the CG-ROM. Games written for it (for example by HAL)
draw their own graphics with it.

The emulation exists only in the MZ-700 emulator (PAL and NTSC). The MZ-800
and the MZ-1500 do not have it: on the MZ-800 in MZ-700 mode the addresses
0E010h-0E012h are ROM, and the MZ-1500 has its own built-in PCG.

> **Note:** the author of the emulator has never seen the device. The
> emulation is based solely on research of information found on the internet
> (the translated HAL manual, an I/O map of the MZ-700, code of programs
> that use the PCG-700). Nothing was measured on real hardware. Where the
> sources disagree, the emulator offers an option (see below); the default
> values are the author's choice, not verified behaviour.

## Connecting

**HW & Devices -> PCG-700 (HAL) -> Connected.** By default the unit is not
connected. The choice is saved in the INI file (section `[PCG700]`, key
`connected`) and also in snapshots.

Connecting the unit is the same as switching its power on: the PCG RAM is
cleared (or filled from the CG-ROM, see *RAM after power on*) and the PCG is
switched off until a program switches it on. A reset of the computer
switches the PCG off again but keeps the RAM.

## How programs use it

The unit has three registers that are written as memory (not with `OUT`):

| Address | Meaning |
|---------|---------|
| 0E010h | pattern byte, one row of a character; bit 7 = left dot |
| 0E011h | PCG RAM address, bits 7-0 |
| 0E012h | bits 1-0 address bits 9-8, bit 2 character set (0 = set 1, 1 = set 2), bit 3 PCG off (1) / on (0), bit 4 write strobe, bit 5 copy the byte from the CG-ROM instead of 0E010h |

The address of a byte is `(code - 80h) * 8 + row`, plus 400h for character
set 2. A program writes the data, the address, then the high address with
bit 4 set (`+ 10h`, or `+ 30h` to copy from the CG-ROM) and then 0E012h
again without bit 4. `POKE $E012,0` switches the PCG on, `POKE $E012,8`
switches it off. The registers are write only; reading these addresses
returns the same as without the unit.

As on the real computer, the upper memory area must be mapped
(`OUT (0E3h)` or `OUT (0E4h)`, the state after reset) when the program
writes the registers.

## Switches and jumpers

The real unit has one switch and two jumpers. In the emulator they are
options in the menu **HW & Devices -> PCG-700 (HAL)**:

| Control | Positions | Meaning | Default |
|---------|-----------|---------|---------|
| HSW switch | PCG / NOM | NOM = PCG off, the standard character set is shown | PCG |
| SSW jumper (software control) | ON / OFF | ON = bit 3 of 0E012h switches the PCG on and off; OFF = software cannot switch it | ON |
| GSW jumper (registers) | ON / OFF | OFF = the registers are disconnected from the bus, all writes are ignored | ON |

HSW NOM only changes what is shown; programs can still write the PCG RAM.

## Options for the disputed details

| Option | Values | Default | Why |
|--------|--------|---------|-----|
| HSW PCG with SSW OFF | PCG on, HSW decides / PCG stays off | PCG on, HSW decides | The manual does not say clearly what is shown with HSW = PCG and SSW = OFF. With the default, the switch alone turns the PCG on (otherwise HSW = PCG with SSW = OFF would be the same as NOM). |
| Write strobe | Rising edge of bit 4 / Every write while bit 4 is set / Falling edge of bit 4 (experimental) | Rising edge | The BASIC example in the manual works with the first two; the sources disagree. The falling edge is experimental: it takes the address from the last write that set bit 4. |
| Decode writes also with DRAM at 0E000h | off / on | off | The manual requires the upper area to be mapped; one source says the unit reacts also when DRAM is at 0E000h (after `OUT (0E1h)`). With this option on, such a write goes both to DRAM and to the unit. |
| RAM after power on | Zeros / Copy of CG-ROM characters | Zeros | Not documented; zeros give the same result on every start. The change applies the next time the unit is connected. |

The other options apply immediately, also to a running program.

## PCG RAM in the debugger

- **HW & Devices -> PCG-700 (HAL) -> Show PCG RAM characters** opens a window
  with the 2 x 128 characters of the PCG RAM and the current state (whether
  the PCG RAM or the CG-ROM is shown, the last value written to 0E012h).
- The Memory Browser shows the RAM in the group *Expansion device* as
  "PCG-700 RAM (2 KB, CG-ROM bit order)". It is stored in the same format as
  the CG-ROM of the emulator (left dot = bit 0), so a byte written to 0E010h
  appears bit-reversed. Editing it changes the characters on the screen
  immediately.
- The I/O Ports window lists the three registers in the section *Expansion
  devices* (only while the unit is connected) with the last written values.

## Remote control (MCP)

The unit has the id `pcg700`: `emu_get_devices` lists it,
`emu_periph_attach` / `emu_periph_detach` with `kind: "pcg700"` connect and
disconnect it, `emu_settings_set` changes the options (`PCG700/hsw`,
`PCG700/ssw`, `PCG700/gsw`, `PCG700/ssw_off`, `PCG700/strobe`,
`PCG700/decode_dram`, `PCG700/poweron_ram`) and the PCG RAM is the region of
kind `device`. See [mcp-server/tools-overview.md](../mcp-server/tools-overview.md).
