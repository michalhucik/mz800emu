# K&P 80 column card (MZ-700) - user documentation

The 80-Zeichen-Karte of Kersten & Partner is an expansion card for the
Sharp MZ-700. It has its own CRTC (Synertek SY6845E), its own 2 KB video
RAM, its own character generator and **its own video output for a second
monitor**: 80 x 25 characters of 8 x 10 dots (640 x 250 dots, about 50 Hz,
monochrome). The picture of the MZ-700 does not change; both pictures
exist side by side and the software chooses where it writes (for example
`SCREEN 0` / `SCREEN 1` in the K&P Disk BASIC). The card has no graphics,
only characters.

The card is available only in the MZ-700 emulator (PAL and NTSC).

> **Note:** the author of the emulator has never seen this card. The
> model is based only on research of information found on the internet
> (a period magazine article with the schematic, the CRTC datasheet and
> the description of a card owner). Nothing was measured on real
> hardware. Details the sources disagree on are options (see below), not
> verified hardware behaviour.

## Connecting the card

Menu **HW & Devices / K&P 80 Column Card / Connected**. The card is
disconnected by default. The choice is saved in the `.ini` file (section
`[KP80]`, key `connected`).

Connecting the card is like switching it on: the CRTC registers are 0 and
the video RAM contains 00h. The second monitor stays dark until a program
sets up the CRTC; until the program clears the screen it is then full of
`@` (code 00h).

The software for the card (for example the K&P Disk BASIC) is not part of
the emulator.

## The second monitor

Window **K&P 80 Column Monitor**:

- opens from **HW & Devices / K&P 80 Column Card / Show 80 Column
  Monitor**, and by itself when you connect the card while the emulator
  is running;
- can be closed and resized; the picture keeps the 4:3 aspect ratio of a
  monitor;
- whether it is open is saved in the `.ini` file (section `[KP80_UI]`).

The phosphor colour of the monitor (white, green or amber) is the option
**Monitor phosphor color**. It changes only the display, not the card.

## Options

Menu **HW & Devices / K&P 80 Column Card**, or all options together in the
window opened by **Settings...** in the same submenu (changes apply with
**OK**, **Cancel** discards them). The two numeric options are set only in
that window; the menu shows their value and opens the window when clicked.
All options apply at once, the card does not have to be reconnected.

| Option (INI key) | Default | Meaning and why this default |
|------------------|---------|------------------------------|
| Read from 70h increments the address (`read_autoinc`) | on | Reading video RAM through port 70h moves the update address to the next byte. The CRTC datasheet says so; the card owner's software sets the address before every read, so it does not depend on it. |
| Write to 71h also writes the selected CRTC register (`data_to_reg`) | on | Following the schematic, a byte written to 71h also reaches the selected CRTC register. Known software selects register 31 before it writes, which makes this harmless. |
| Update address (R18/R19) takes effect on R31 access (`addr_on_r31`) | on | A new video RAM address becomes valid only after an access to register 31, as the datasheet and the card owner describe. Off = the address changes at once. |
| Update cycle length (character clocks) (`update_delay`) | 0 | How long status bit 7 stays 0 after a video RAM access (character clock = 2 MHz). The real timing is unknown; 0 = always ready. |
| WAIT on ports 71h - 73h (T-states) (`wait`) | 0 | The card briefly holds the CPU with WAIT on these ports; the length is unknown. 0 = no extra delay. A port read or write from the debugger (I/O window, MCP, breakpoint condition `port[N]!`) adds no WAIT. |
| Monitor phosphor color (`phosphor`) | white | Display colour of the second monitor: White, Green, Amber in the menu (`white`, `green`, `amber` in the INI file). |

In the `.ini` file the numbers of `update_delay` and `wait` are read as
hexadecimal (`wait = 10` means 16).

## Ports and registers (for programmers)

| Port | IN | OUT |
|------|----|-----|
| 70h | byte of video RAM at the update address | - |
| 71h | selected CRTC register | byte to video RAM at the update address, the address moves to the next byte (option: also into the selected register) |
| 72h | status: bit 7 update ready, bit 6 light pen (always 0), bit 5 vertical blanking | select CRTC register (bits 0 - 4) |
| 73h | selected CRTC register | selected CRTC register |

The ports are decoded fully (no mirrors).

The video RAM is reached only through the CRTC (transparent mode, R8 =
78h): R18/R19 = address, an access to R31 confirms the address, status
bit 7 = ready. Write sequence:

```
        LD   A,18          ; R18 = high byte of the address
        OUT  (72h),A
        LD   A,H
        OUT  (73h),A
        LD   A,19          ; R19 = low byte
        OUT  (72h),A
        LD   A,L
        OUT  (73h),A
        LD   A,31          ; select R31 = confirm the address
        OUT  (72h),A
RDY:    IN   A,(72h)       ; wait for update ready
        RLCA
        JR   NC,RDY
        LD   A,'A'
        OUT  (71h),A       ; character to video RAM, address + 1
```

Initialisation used by the card owner's software, R0 - R15: `7Fh 50h 64h
0Ch 1Eh 02h 19h 1Ch 78h 09h 60h 09h 00h 00h 00h 00h` (80 x 25, 10 lines
per character, blinking cursor). Display start R12/R13 (scroll: add 80,
modulo 2048), cursor position R14/R15, cursor shape R10/R11.

Registers R14 - R17 can be read; the other registers read as 0. The video
RAM has 2048 bytes, addresses are taken modulo 2048.

## Font and characters

The character generator is built into the emulator (the card's EPROM,
128 characters of 8 x 16 dots, the picture uses 10 lines of each). Codes
00h - 7Fh are a German variant of ASCII (for example 40h = `§`, 5Bh - 5Dh
= `Ä Ö Ü`, 7Bh - 7Eh = `ä ö ü ß`). Bit 7 of a code shows the character
inverted.

## Power on and reset

- Connecting the card = power on: registers 0, video RAM 00h, dark
  monitor.
- **Reset** of the MZ-700 does not clear the card: registers and video RAM
  stay, the second monitor keeps its picture until the software sets the
  card up again. (Choice of the model: per the datasheet the CRTC reset
  input stops only the counters.)

## Snapshots and debugger

- A snapshot (`.mzs`) stores whether the card is connected, its options,
  registers and video RAM.
- Debugger: the I/O window lists ports 70h - 73h in the section Expansion
  devices; the Memory Browser shows the card video RAM (writable), the
  font and the CRTC registers (read only).
- MCP: the picture of the second monitor is available with the tool
  `emu_device_screenshot` (see the MCP documentation).
